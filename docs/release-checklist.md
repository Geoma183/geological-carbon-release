# Public release checklist

This is a planning checklist, **not** a record of passed checks.

## Manuscript identity and provenance

- [ ] Identify the exact submission manuscript and supporting-information versions.
- [ ] Identify the canonical data and code outputs used by each figure/table.
- [ ] Reconcile all reported totals, units, years, uncertainty bounds, and boundaries.
- [ ] Label formal results, model estimates, preliminary estimates, and hypotheses distinctly.
- [ ] Remove supervisor annotations, internal review text, and tracked revisions.

## Data rights and governance

- [ ] Register dataset providers, source URLs/DOIs, versions, access dates, permissions, and attribution.
- [ ] Check redistribution rights for every external input.
- [ ] Provide access instructions instead of publishing restricted original datasets.
- [ ] Preserve raw and processed data separately.
- [ ] Record missing values distinctly from zero and not-applicable values.
- [ ] Publish coverage and historical mapping rules.

## Reproduction

- [ ] Remove credentials, personal paths, internal communications, and confidential metadata.
- [ ] Publish vetted code, parameters, dependencies, and tested commands.
- [ ] Reproduce tables/figures and log numerical validation results.
- [ ] Provide a clear source-to-figure result index and known limitations.

## Public release

- [ ] Obtain research-team approval for public content.
- [ ] Choose separate appropriate code/data licenses after rights review.
- [ ] Tag a frozen GitHub release following successful checks.
- [ ] Create a Zenodo archive, verify contents, and cite the actual minted DOI.
- [ ] Ensure the journal manuscript links to the exact archived dataset version.
